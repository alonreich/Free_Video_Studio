-----------------------------------------------------------------------------------------------
Several AI agents may work on this file one after another (or at the same time). To keep one
continuous flow and never do the same work twice:

  0.1  Every sub-task line starts with a STATUS tag:
         [TODO]                         not started
         [CLAIMED <agent/session> <date-time>]   someone is working on it NOW
         [DONE <agent/session> <date-time>]      finished, tests green, docs updated
         [BLOCKED <reason>]             cannot proceed; reason says who must answer what
         [SKIPPED <reason>]             owner decided not to do it
  0.2  BEFORE starting a sub-task: re-read this file from disk, pick the FIRST [TODO] whose
       "Depends on" are all [DONE], change it to [CLAIMED ...] and SAVE THE FILE IMMEDIATELY.
       Never start a task someone else has CLAIMED unless the claim is older than 24 hours
       AND nothing in git shows progress — then note "re-claimed, previous claim stale".
  0.3  WHEN FINISHED: set [DONE ...], add 1–3 lines under the task ("Result:" — files touched,
       tests added, anything the next agent must know). Save. Then take the next task.
  0.4  If you stop half-way: leave it [CLAIMED] and add "Progress:" lines describing exactly
       what is finished and what is not, so the next agent can resume.

       numbered with a letter suffix (e.g. P2.3a), status [TODO], and say why.

           waiting for the owner.
         - Code proposals to the owner use: FILE / OLD CODE (2 lines context) / NEW CODE.
         - If unsure or guessing: say so ("WARNING: FACT CHECK REQUIRED.") and ask.
         - NO LOCAL AI MODELS, ever (no Whisper, no ONNX, no Ollama, no on-device trackers
           presented as "AI"). Cloud only, and only these vendors: Google (Gemini),

5. PHASE P2 — LIVE COMMENTARY CAPTIONS ("karaoke" first-person scene narration)
-----------------------------------------------------------------------------------------------
Owner's idea (approved to plan): moving, karaoke-style captions that narrate what happens, in
the player's first-person voice, e.g.
  "I've taken a lot of damage, so I'm repositioning and trying to heal."
  "He ran away, so I chased him till death do us part."
  "His teammate hit me, so I had to shockwave and reposition."
Requirements: must not bother the picture; must wrap nicely inside the narrow PORTRAIT width
(the canvas trick: only the 720-source-px centre slice survives; final 1080x1920 with a
1080x1620 content area and 150 px top/bottom voids); also work in landscape exports.

Design decisions (proposed — confirm with owner where marked ASK):
  D1 Input to the AI: Gemini — the real clip WITH AUDIO (hit/shot sounds matter), chunked
     like AICHUNK_01; Claude/OpenAI — timestamped frames (P1.6) (+ optionally transcript-free).
     Context in prompt: game profile, "which character is me" (default: third-person = the
     avatar in the lower centre; first-person = the camera), tone preset (Hype / Chill /
     Funny / Tactical — ASK owner for list), language, optional user notes.
  D2 Output schema: [{start, end, text, emphasis:[words], confidence}] in SOURCE seconds;
     first person; ≤ ~8 words per line, ≤ 2 lines on screen; no line shorter than 1.2 s;
     gaps allowed when nothing notable happens; never invent kills/damage not visible.
  D3 Timing: map source → output time through OutputTimeline/CompositeTimeline (speed ramps,
     cuts, freezes, full-screen meme insertions). Lines falling inside a cut are dropped; a
     line spanning a speed change is re-timed; karaoke word timing distributed by syllables
     over the mapped span.
  D4 Placement (portrait): default in the LOWER part of the content area, inside the centre
     slice width, ABOVE the bottom 150 px nav void, and avoiding HUD layers of the active crop
     profile (crops_1080p rects in content space) — automatically move up if a HUD layer is
     there. Max width = content width minus safe margins (≈ 960 px of 1080; ASK) with
     word-wrap; font size scaled to the 1080-wide canvas. Alternative position presets:
     "Bottom (default)", "Top (under title)", "Bottom void" (inside the 150 px strip — only
     if no nav mockup; ASK). Landscape: lower third, 16:9 safe area.
  D5 Style: karaoke word highlight (ASS \k / \kf), outline + shadow for readability on any
     footage, theme-independent colour tokens, optional emoji off by default. Presets: Karaoke,
     Pop-in words, Typewriter. ASK owner which first.
  D6 Rendering: ASS subtitles burned in by FFmpeg (needs libass in binaries/ffmpeg.exe —
     verify) and shown in preview by libmpv (native ASS) → preview = export. Fallback if no
     libass: per-line PNG via SkiaSharp (TextOverlayGenerator) + overlay (no per-word karaoke).
  D7 Editing: a "Captions" lane on the timeline; edit text, drag start/end, regenerate one
     line, delete, undo/redo (docs/07), saved in .fvsproj (docs/06 schema + amputation rule),
     recovery-safe (docs/05).
  D8 Privacy/consent: same pattern as AIZOOMCONSENT_01, naming the vendor and saying audio is
     sent (Gemini path).
